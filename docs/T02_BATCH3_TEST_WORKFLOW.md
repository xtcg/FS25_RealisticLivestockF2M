## 正常活卖：OFF → SHADOW → TEST

控制台在服务器执行；地图加载后模式回OFF。

```text
rlTradeSaleMode
rlTradeSaleMode OFF
rlTradeTxReport
rlTradeSaleMode SHADOW
rlTradeSaleMode TEST
rlTradeTxReport
rlTradeTxReport <实际日志中的txId>
```

1. **OFF基线**：人工单头与牧工单头分别执行，核对旧路径删除、钱和工资；报告无本次新增活卖记录。
2. **SHADOW**：准备另一组相同条件样本；人工出售仍走旧路径，日志显示候选事务支持/拒绝原因，不能新增账本、锁或收据。
3. **TEST人工单头**（S01）：核对售款为卖价减运费、动物离源一次、APPLIED/COMMITTED、正常成功回复和圈舍消息。
4. **TEST人工多头**（S01/S10）：逐头累加净额，与钱包、财务统计、HUD金额及报告一致；按实际精度核对，不只比较显示舍入。
5. **TEST拖车**（S18）：通过正常拖车出售入口，核对拖车报价/运费口径、动物集合与客户端同步；无圈舍消息是预期。
6. **TEST牧工**（S13–S16）：配置单头、多头及同农场多个出售动作，执行正常日轮次；售款沿用卖价加运费，工资独立扣除。易主不收工资，拒售/失败按原工资规则处理；mark只标记。
7. **出售后买入**（S16）：核对真实钱包与空位；待核对事务持有现金锁时，牧工buy应为cash-held。先用可复现测试钩子制造待核对状态。
8. 对每步收集游戏日志、报告、前后动物身份与金额。正常成交不能出现UNKNOWN或未释放锁；如出现，记失败并保留完整证据。

## 评审修复与异常场景

以下已离线验证。游戏内只在专用测试钩子能够定位阶段时执行；当前没有提供控制台故障注入命令，也没有重放roundId的玩家命令。无钩子记阻塞，不用普通按钮连点冒充同ID重放。

| 案例 | 注入位置与输入 | 预期 |
|---|---|---|
| S02/S09 | 两头部分移除，付款监听器把幸存动物再次加入待删队列 | 只付确认子集；付款后清理本批队列；后续flush保留未付款幸存动物 |
| S04/S07 | addMoney包装函数先排队移除批外动物，然后在修改资金前抛错 | NOT_APPLIED；恢复不flush外部队列；不能删批外动物；恢复不可证明则待核对并持锁 |
| S09 | MONEY_CHANGED监听器重新添加已售动物 | 付款保持APPLIED；SOURCE_CHANGED_AFTER_SETTLEMENT、NEEDS_RECONCILIATION；来源数量未知；不二次付款、不释放锁 |
| S08/S14 | 固定saleId/roundId，首次疾病报价拒绝或prepare队列忙；解除原因后重放 | 返回首次拒绝，replayed；不出售、不再贡献工资；同ID更换payload为ID_COLLISION |
| S05/S06/S15 | 付款/工资在不同步骤抛错、字段不可读或额外资金变化 | 按完整证据区分APPLIED/NOT_APPLIED/UNKNOWN；UNKNOWN不补款、不复活；工资动作不再次扣除 |
| S03/S07/S11 | 来源不可读、恢复/视觉/通知失败 | 不冒报成功；保留阶段证据；成交后通知失败不能触发再次付款 |

UNKNOWN没有自动补款、解锁或恢复工具。记录证据后结束该故障样本，其他场景使用独立复制存档；不能以重载后锁消失判定问题已恢复。
