## 2. 每轮执行顺序

1. **固定构建**：记录 base/head、工作区差异、PR、实际mod包哈希与modDesc版本。
   排除同名mod重复包，确认游戏加载的是该测试包。
2. **固定输入**：备份测试存档；记录HB Beta2、模组加载顺序、难度、月长、资金、
   自定义carcassYield/bodyCondition配置、ET/SellPrices/PF及其他修改经济/动物的mod。
3. **离线回归**：在对应工作树运行 `python tests/run.py`，保留完整日志/退出码；
   记录实际 Lua 解释器版本。比较基线测试数量，说明新增/删除案例原因。
4. **只读游戏冒烟**：先跑T01 `rlTradeReport`，再跑`rlTradePlan`。
   先固定时间、关闭自动任务，比较查询前后动物、订单、钱包、库存。
5. **正常成交**：复制测试存档，按单头→多头→多订单→容量/资金边界验证。
6. **异常注入**：先离线再在专用测试环境执行；使用可定位阶段的开发钩子。
   不靠随机拔网线或崩溃来代替可复现案例。生产存档不做资产异常注入。
7. **保存与联机**：使用当前 dev 验证保存重载，并分别记录单机、主机和专服结果。
8. **记录结果**：按第11节填结果；失败关联issue/修复提交，复测保留原失败记录。

暂停时间只能排除常规小时推进，不能替代提交时权限、配置、预算和版本复核。

## 9. 数量、成本和观测口径

每个正常/失败案例至少记录：来源成员身份列表、目标订单ID/配方版本、
buffered/totalDelivered/totalDeliveredAmount、ready与其他产出、fee/feeCredit、
农场钱包及对应统计、队列、事务阶段/锁、客户端提示、视觉计数。

公共输入为标准批次，不是kg；农场输入为生产单位；生产后成品按有效配方和时间核对。
农场运行费按实际活跃小时；运输、托盘/领取费用单列；信用预付与当次成本不重复计。
单次查询的预计肉量不是已经生产的成品，更不是已经卖出的现金。

double等价、显示舍入、网络float32分别规定容差。承诺完整接纳必须同时核对
语义完整性和真实资产增量；不得把足以容纳一个部分接纳的容差当作整头成功。
