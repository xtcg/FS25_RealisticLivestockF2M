# 商人收购合同首版

基于 PR #95，模组版本 `0.2.2.2`。当前交付为可玩候选版：单机、Angus 断奶小牛、月度共享额度、牧场接运、逐只确认及正常保存重载。商人收购默认开启，未做实机验收；自送、猪羊及多人尚未开放。

## 使用

1. 安装候选包进入单机存档，首次使用先正常保存一次游戏。
2. 打开游戏暂停菜单的“设置”页，鼠标点击“商人收购合同 / 查看收购需求”，直接进入收购页。
3. 查看需求、条件、到期时间及订单/牛类/品种三层余量。
4. 选择自己圈舍里的 Angus 牛，查看资格、拒收原因和净收入明细。
5. 对合格动物请求接运报价，在 15 秒内逐只确认。每次只交付一只。
6. 正常保存；重载后核对动物、资金和剩余额度。

默认每月一单 4 头需求，牛类月额度 8、Angus 月额度 4，因此首版实际最多成交 4 头。三层额度独立执行。只浏览、换选择或预检不会占额度、扣动物或付款。

全流程可用鼠标操作。暂停菜单的“RLRM 设置”按钮可进入“设置→常规”，其中提供“商人收购”开关（默认开）和“查看收购需求”按钮。关闭会立即拒绝新的报价/确认，但保留订单、额度、已成交结果和恢复证据；重新开启不会重置额度，也不能解除不明交易的锁。开关随存档设置保存。首次正常保存的共同证据门槛仍保留。

条件为 4–10 月龄、健康至少 80、已断奶、发育月龄至少 4、体重为个体生长参考的 75%–120%，未妊娠、未产奶。运输前净额封顶于当前商人卖价及同状态买价的 90%，接运费为普通原生运输费的一半；没有来源或完成奖励。详细依据见 [首批牛类证据](evidence/broker-cattle-release.md)。

## 保存与恢复

订单、额度、事务、身份、原生动物文件和农场资金使用共同保存证据。资金或持久化结果不明时保留证据并暂停，不自动退款、不重造动物、不重放付款；下一次保存继续携带暂停标记及原 WAL。

交付后直接退出而没有保存，会留下旧世界状态与新 WAL 的不一致，收购和旧交易渠道会暂停；保留日志及存档证据供核对。正常“成交→保存完成→退出→重载”已通过联合 XML 离线测试，仍需实机复验。

### 暂停后的恢复

控制台命令 `rlBrokerStatus`（只读）显示状态、暂停原因和携带的恢复标记；`rlBrokerRecoveryClear`（单机、服务端）在读完证据后解除暂停，并重新做完整启动验证：

- 读档后立刻执行（本次会话还没有做过收购成交）。若已保存的检查点仍能对世界证明一致，而实时 WAL 多出未保存的成交，则把该 WAL 复制为 `rm_RlBrokerLive_broker.unsaved.<时间>.xml`（及 `.staging`），再用检查点文档替换它；订单、额度回到保存点，与世界一致。引擎禁止 mod 删除存档目录文件，因此保留的是复制品，下次保存会随存档目录一并替换。
- 本次会话已做过成交则拒绝（`BROKER_RECOVERY_RELOAD_REQUIRED`），应读取上一次存档。
- 暂停期间做过保存的存档，其 careerSavegame 内容已含恢复标记，无法再证明检查点，清除命令会拒绝并保持关闭；这属于资金归属不明，需要人工核对证据。
- 尚无任何持久化证据时，仅范围类标记（例如重复身份键）不会被写入存档，已写入的标记可被清除。
- 身份账本在读档时处于 RECOVERY_REQUIRED、之后用 `rlIdentityRecoveryClear` 恢复为 READY 的，收购会自动重新评估并解除保持，不必重启游戏。

首次保存前若上一次会话已生成未来月份的需求，重新载入时按游戏日期恢复并复用这些需求，不会重抽也不会进入时钟回退暂停。

只有未保存月度需求发生过变化时，复用未来已生成的需求，不重新抽单。尚无资产风险的初始范围不支持只关闭 Broker；已有不明资产结果时，相关旧交易渠道也受保护。

## HB 与实机核对

本地 `hb_1.5b1` 的 `1.5.0.0 Beta1` 附加专精已作受限读取适配。其他 HB 版本、第三方动物存储布局需单独核验。

最短实机路径：独立测试档中查看合格和拒收样本，确认一只，核对动物少一、资金增加所示净额、三层额度各少一；保存退出重载后再核对。随后检查取消、过期、跨月、旧渠道互斥及不完整保存的暂停行为。
